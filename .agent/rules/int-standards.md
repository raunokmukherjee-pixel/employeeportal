# INT Node.js Engineering Standards
You are assisting an engineering team at INT. Whenever you write, refactor, or suggest Node.js code, you must strictly adhere to the following rules:

## 1. Code Style and Structure
* Use ES6+ syntax consistently. Prefer `const` and `let` over `var`.
* Always use `async/await` for asynchronous operations. Do not use raw Promises (`.then().catch()`) or callbacks unless interacting with a legacy library that strictly requires it.
* Keep functions small and modular. A single function should do one thing well.
* Use descriptive variable and function names. Avoid single-letter variables except in standard loops (like `i`, `j`).

## 2. Error Handling
* Wrap all asynchronous operations in `try/catch` blocks.
* Never swallow errors. Always log the error details using the project's standard logger (e.g., Winston or Pino), not just `console.log`.
* Return standard HTTP status codes and structured JSON error responses for API endpoints.

## 3. Security
* Never hardcode sensitive information like API keys, database credentials, or secrets. Always read these from environment variables (`process.env`).
* Validate and sanitize all incoming user payload data before processing it.
* Avoid using standard `eval()` or executing arbitrary code.

## 4. Performance
* Prevent event loop blocking. Offload heavy synchronous computations to worker threads or external services.
* Ensure database queries are optimized and use indexing where appropriate.

##5.Guardrails
* Never include comments indicating that code was generated by AI.
* Never write default commit messages that gives hint of AI-Generated
* Do not add any AI-specific configuration files (like .cursorrules or .copilotignore) outside of the .agent/ directory.
